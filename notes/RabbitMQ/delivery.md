# Гарантии доставки

## At-Most-Once (максимум одна доставка)
<!-- middle 3525480 -->
- **Как работает**: Сообщение теряется, если брокер или consumer не успели его обработать.
- **Когда используется**:
    - Без `publisher confirms` (отправка без подтверждения).
    - С `auto_ack=True` (consumer автоматически подтверждает получение).
- **Проблема**: Возможна потеря сообщений.

## At-Least-Once (минимум одна доставка)
<!-- middle 3525480 -->
Это основная модель RabbitMQ.  
- **Как работает**:
    - **Publisher Confirms** гарантируют, что сообщение дошло до брокера.
    - **Manual Acknowledgements (`ack`/`nack`)** гарантируют, что consumer обработал сообщение.
    - Если `ack` не пришло, RabbitMQ перенаправляет сообщение другому consumer'у.
- **Риск**: Возможны **дубли** (если `ack` не дошёл из-за ошибки, но сообщение уже обработано).
- **Пример**:
  ```python
  """Publisher (гарантия отправки) """
  channel.confirm_delivery()  # Включить подтверждения
  channel.basic_publish(..., properties=pika.BasicProperties(delivery_mode=2))  # Persistent

  """ Consumer (гарантия обработки) """
  def callback(ch, method, properties, body):
      try:
          process(body)
          ch.basic_ack(delivery_tag=method.delivery_tag)  # Ручное подтверждение
      except:
          ch.basic_nack(delivery_tag=method.delivery_tag, requeue=True)  # Повтор
  ```

## Exactly-Once (только одна доставка)
<!-- middle 3525480 -->
Не поддерживается напрямую.  
- **Проблема**: RabbitMQ не предоставляет встроенного exactly-once, так как это требует координации между producer и consumer, что сложно в распределённых системах.
- **Как эмулировать**:
    1. **Идемпотентность обработки** – проверять, обрабатывалось ли сообщение ранее (например, по `message_id`).
    2. **Транзакции + дедупликация** (не рекомендуется из-за производительности).
    3. **Внешние системы** (например, БД с уникальными ключами для дедупликации).
- **Пример (идемпотентный consumer)**:
  ```python
  processed_ids = set()  # Внешнее хранилище (Redis, БД)

  def callback(ch, method, properties, body):
      if properties.message_id in processed_ids:
          ch.basic_ack(delivery_tag=method.delivery_tag)  # Уже обработано
          return
      process(body)
      processed_ids.add(properties.message_id)
      ch.basic_ack(delivery_tag=method.delivery_tag)
  ```

## Сравнение гарантий доставки
<!-- middle 3525480 -->
| Гарантия         | Поддержка в RabbitMQ | Риски                          | Как добиться                          |  
|------------------|----------------------|--------------------------------|---------------------------------------|  
| **At-Most-Once** | Да                   | Потеря сообщений               | `auto_ack=True`, нет подтверждений    |  
| **At-Least-Once**| Да (рекомендуется)   | Дубли (если `ack` не дошёл)    | `publisher confirms` + `manual ack`   |  
| **Exactly-Once** | Нет (только эмуляция)| Сложность реализации           | Идемпотентность + внешняя дедупликация|  

- **Для большинства сценариев** хватает **at-least-once** (с подтверждениями и persistent-сообщениями).
- **Exactly-once** требует дополнительных усилий (идемпотентность, дедупликация).
- **At-most-once** подходит для неважных данных, где допустимы потери.

Если вам критична **строгая однократная доставка**, рассмотрите Kafka с её exactly-once семантикой или реализуйте дедупликацию поверх RabbitMQ.

В RabbitMQ есть несколько механизмов, которые обеспечивают **гарантии доставки** сообщений. Однако важно понимать, что RabbitMQ по умолчанию не гарантирует 100% доставку — это зависит от настроек и корректного использования клиентами.

## Publisher Confirms
<!-- middle 3525480 -->
Подтверждение доставки.  
- **Как работает**: После отправки сообщения брокер подтверждает его получение (`ack`).
- **Когда использовать**: Для гарантии, что сообщение точно дошло до брокера.
- **Настройка**:
  ```python
  channel.confirm_delivery()  # Включение подтверждений
  ```  
  Если брокер не подтвердил доставку, можно повторить отправку.

## Consumer Acknowledgements
<!-- middle 3525480 -->
Подтверждение обработки.  
- **Как работает**: Потребитель (consumer) явно подтверждает (`ack`), что обработал сообщение. Если `ack` не пришло, RabbitMQ может перенаправить сообщение другому потребителю.
- **Режимы**:
  - **Автоподтверждение (`auto_ack=True`)** – сообщение считается доставленным сразу после отправки (ненадёжно).
  - **Ручное подтверждение (`auto_ack=False`)** – consumer сам отправляет `ack` или `nack` (надежно).
- **Пример (Python, `pika`)**:
  ```python
  def callback(ch, method, properties, body):
      try:
          process_message(body)
          ch.basic_ack(delivery_tag=method.delivery_tag)  # Подтверждение
      except Exception:
          ch.basic_nack(delivery_tag=method.delivery_tag, requeue=True)  # Отказ + возврат в очередь
  ```
