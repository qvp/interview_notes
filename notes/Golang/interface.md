# Interface

## Использование в golang
<!-- junior 3525480 -->
В Go используется подход "утиной типизации" (duck typing) для интерфейсов: тип автоматически реализует интерфейс, если содержит все его методы.  
Позволяют писать более гибкие функции, не привязанные к деталям одной, конкретной реализации.  
В Го интерфейсы удовлетворяются неявно - нет необходимости писать все интерфейсы, которым соответствует данный конкретный тип, достаточно только наличия необходимых методов.  
Интерфейс является абстрактным типом, который не раскрывает представление или внутреннюю структуру значений, он показывает только некоторые из их методов.  
Тип соответствует интерфейсу если у него есть все методы объявленные в интерфейсе.  
Код будет меньше зависеть от другого кода если описывать интерфейс на принимающей стороне.  

Если методы интерфейса определены для типа (value receiver), то и сам тип, и его указатель удовлетворяют интерфейсу. Если методы определены для указателя (pointer receiver), то только указатель на тип удовлетворяет интерфейсу.
```go
type Animal interface {
	Speak() string
}

type Cat struct{}

// Метод с pointer receiver
func (c *Cat) Speak() string {
	return "Meow!"
}

var a Animal

c := Cat{}
a = c // Ошибка! Cat не реализует Animal
// только *Cat реализует Animal

pc := &Cat{}
a = pc // Работает
fmt.Println(a.Speak())
```

## Динамический тип интерфейса
<!-- junior 3525480 -->
Это конкретный тип, который в данный момент хранится в переменной интерфейса. Когда вы присваиваете значение интерфейсу, Go сохраняет как значение, так и его исходный (динамический) тип.
```go
var i interface{}  // статический тип интерфейса - interface{}
i = 42            // динамический тип - int
i = "hell"       // теперь динамический тип - string
```

## Динамическое значение интерфейса
<!-- junior 3525480 -->
Это конкретное значение, которое в данный момент хранится в переменной интерфейса. Оно соответствует динамическому типу.
```go
var writer io.Writer

// Динамический тип: *os.File
// Динамическое значение: конкретный файл
writer = os.Stdout
```
Интерфейс равен nil только если и его динамический тип, и динамическое значение равны nil.
```go
var buf *[]byte        // buf == nil (нулевой указатель на срез)
var writer io.Writer   // writer == nil (интерфейс без типа и значения)

writer = buf           // Теперь writer содержит:
                       // Динамический тип: *[]byte
                       // Динамическое значение: nil

fmt.Println(writer == nil) // false, потому что динамический тип *[]byte не nil!
```

## Пустой интерфейс
<!-- junior 3525480 -->
Пустой интерфейс занимает 0 байт и ему соответствует любой тип данных (можно использовать вместо джереников).  

## Динамическая диспетчеризация
<!-- junior 3525480 -->
Это механизм, при котором конкретная реализация метода выбирается во время выполнения программы на основе типа объекта, а не во время компиляции.  
В Go динамическая диспетчеризация работает только при использовании интерфейсов.  
Таблица методов - для каждого типа Go создает таблицу методов (method table), которая используется для поиска нужной реализации.  
Позднее связывание - конкретный метод определяется во время выполнения программы.  

В Go динамическая диспетчеризация реализована эффективно и является ключевым механизмом для достижения гибкости без использования классического наследования:
* Полиморфного поведения
* Реализации паттернов проектирования (стратегия, команда и др.)
* Создания гибких API
* Тестирования (моки через интерфейсы)
* Плагинных архитектур

## embedded
<!-- junior 3525480 -->
Встроенные интерфейсы объединяют свои методы.  
Результирующий интерфейс требует реализации всех методов встроенных интерфейсов.  
Нет ограничения на количество встраиваемых интерфейсов.  
Если встраиваемые интерфейсы содержат методы с одинаковыми именами и сигнатурами, они объединяются в один метод, если сигнатуры различаются - возникает ошибка компиляции.  

```go
io.ReadWriteCloser
```
