# Channels

## Общие сведения
Каналы это механизм обменна данными между горутинами, а так же средство их синхронизации.  
Каналы goroutine-safe, так как там внутри уже есть мьютекс.  
Работают по принципу FIFO.  
Могут использоваться для передачи данных, блокировок, завершения работы goroutine.
Располагаются в куче.  
При поступлении в канал данные копируются (если не передается тип ссылка).  

## Не буферизованные каналы
Блокируют отправку до тех пор, пока другая горутина не примет данные. Они дают более надежные гарантии синхронизации, потому что каждая операция отправления синхронизируется с соответствующей операцией получения.

## Буферизованный канал
Позволяют отправлять данные без блокировки, пока буфер не заполнится. Длинна буфера ограничена памятью и типом данных канала.  
Емкость буфера канала ограничивает количество одновременных запросов, которые он может хранить.  
Если прочитать сообщение из заполненного канала он снова перестанет блокировать. Емкость буфера можно узнать с помощью функции `cap`.
Операции записи и чтения из канала разделены, что может приводить к логическим ошибкам.
Буферизованный канал помогает сглаживать нагрузку между горутинами ну или служить ограничением параллелизма горутин.

## Направление
Каналы могут быть однонаправленными (только для отправки или только для получения) или двунаправленными (для отправки и получения).

## Проверка закрытия канала
`value, ok := <-ch`, где `ok` true если канал открыт.

## Select
Позволяет ждать операций на нескольких каналах. Если сразу несколько каналов активны - будет выбран случайным образом.
Вариант `default` позволяет не ждать сообщения в каналах, а сразу выполнить код.
Опрос канала - вызов `select` в цикле.  
`select` будет бесконечно читать из закрытого канала если ему не присвоить значение `nil`, так как операция чтения из закрытого канала всегда успешна.  

Выбор `case` внутри `select` происходит случайным образом.  

Минусы каналов - они не очень быстрые, альтернативно можно использовать (мьютексы, указатели?).

Если каналов в select несколько, то ожидающая горутина попадает в один из recevq канала, но не во все сразу (структура sudog).

## Broadcasting
Оповещение нескольких горутин о каком-то событии или рассылка сообщения всем горутинам.  

Если нужно просто сообщить о завершении:
1. Закрытие канала предназначенного специально для этих целей
2. Использование условной переменной, например `sync.Cond`
3. Использование `context.Context`

Если нужно рассылать данные во все горутины, то необходимо создавать по отдельному каналу на каждую горутины и отправлять данные в каждый из них.

## Структура канала
Внутри канал представлен структурой runtime.hchan
```go
type hchan struct {
    qcount   uint           // количество элементов в буфере
    dataqsiz uint           // размер буфера (ёмкость)
    buf      unsafe.Pointer // указатель на кольцевой буфер
    elemsize uint16         // размер одного элемента
    closed   uint32         // флаг закрытия канала
    elemtype *_type         // тип элементов канала
    sendx    uint           // индекс записи в буфер
    recvx    uint           // индекс чтения из буфера
    recvq    waitq          // очередь ожидающих получателей (горутин)
    sendq    waitq          // очередь ожидающих отправителей (горутин)
    lock     mutex          // мьютекс для синхронизации
}
```
Буфер представляет собой кольцевую очередь.  

https://github.com/golang/go/blob/master/src/runtime/chan.go  

## Отправка в канал
1. **Блокировка мьютекса** (`lock`).
2. Если есть ожидающий получатель (`recvq` не пуст):
    - элемент **копируется напрямую** в получателя.
    - разблокируется мьютекс.
3. Если буфер не заполнен (`qcount < dataqsiz`):
    - элемент кладётся в буфер (`buf`).
    - `sendx` и `qcount` обновляются.
4. Если буфер заполнен:
    - текущая горутина **блокируется** и добавляется в `sendq`.
    - мьютекс разблокируется, горутина засыпает.
5. При появлении получателя горутина **пробуждается**, и данные передаются.

## Получение из канала
1. **Блокировка мьютекса** (`lock`).
2. Если канал закрыт и буфер пуст — возвращается нулевое значение.
3. Если есть ожидающий отправитель (`sendq` не пуст):
    - элемент **берётся напрямую** из отправителя (или из буфера, если он есть).
4. Если в буфере есть данные (`qcount > 0`):
    - элемент забирается из буфера (`buf[recvx]`).
    - `recvx` и `qcount` обновляются.
5. Если буфер пуст:
    - горутина **блокируется** и добавляется в `recvq`.
    - мьютекс разблокируется, горутина засыпает.
6. При появлении отправителя горутина **пробуждается** и получает данные.

## Блокировки и синхронизация
- **Мьютекс (`lock`)**: защищает все операции с каналом.
- **Очереди (`sendq`, `recvq`)**: списки горутин, ожидающих отправки/получения.
- **Условные переменные**: пробуждают горутины при появлении данных/места в буфере.

## Закрытие канала
Закрытие канала выполняется отправителем, а не получателем, чтобы не было паники при попытке отправителя записать в уже закрытый канал.  
Используют второй "сигнальный" канал (или контекст) для уведомления отправителя если нужно закрыть канал со стороны получателя.  

1. Устанавливается флаг `closed = 1`.
2. Все горутины из `recvq` получают нулевые значения.
3. Все горутины из `sendq` паникуют (`panic: send on closed channel`).

## Особые случаи
- **Не буферизованный канал**
    - `dataqsiz = 0`, все операции **синхронные** (отправитель ждёт получателя и наоборот).
- **Буферизованный канал**
    - отправка не блокируется, пока буфер не заполнен.
- **`nil`-канал (`var ch chan int`)**
    - любая операция с ним блокируется навсегда (может привести к deadlock).

## Где хранятся данные канала
* Если канал буферизованный, данные лежат в кольцевом буфере (buf) в структуре hchan.
* Если канал небуферизованный (или буфер заполнен/пуст), данные передаются напрямую между стеками горутин.

## Debug chan
В стандартной библиотеке Go нет встроенного режима отладки для каналов. Однако можно использовать несколько подходов для отладки:
* Использовать дебагер из Goland.
* В пакете `runtime.chan` установить константу `debugChan=true`.
* Обёртка над каналом с логированием.
* Использование race detector для выявления гонок. `go run -race main.go`
* Использовать профайлер runtime/pprof.
* Использовать трассировку runtime/trace.
* github.com/felixge/fgprof может показать, где горутины проводят время.
* Использовать select с таймаутами в подозрительных местах.

## Deadlock
Возникает, когда горутины бесконечно ждут друг друга, и программа зависает.
* Все горутины заблокированы (нет получателя/отправителя)
* Закрытый канал
* Все горутины завершились, но канал не закрыт
* Забыли закрыть канал в select с default

Нужно закрывать канал с помощью `close(ch)` чтобы избежать блокировки горутин.

## Закрытие канала
Это операция, которая меняет внутреннее состояние канала и уведомляет все заблокированные горутины.  
Происходит разблокировка всех горутин из recvq (ожидающих чтения). Все горутины, заблокированные в <-ch, получают нулевое значение.  
Паника для горутин из sendq (ожидающих записи).  
Освобождается мьютекс канала.  

При закрытии `nil` канала происходит паника.  
При повторном закрытии канала происходит паника.  
`range` по каналу завершается при `close(ch)`.  

Если нужно безопасно работать с каналами, лучше использовать шаблоны типа "закрытие через defer" и проверку ok при чтении.  

## Механизм блокировки и пробуждения
1. **Парковка горутины**:
    - При выполнении `select` с несколькими каналами, горутина регистрирует себя во всех каналах из case-ов
    - Затем горутина "паркуется" (переходит в спящее состояние)
    - Это делается через вызов `gopark` в рантайме Go, который переводит горутину в ожидание

2. **Пробуждение горутины**:
    - Когда в любом из каналов происходит операция (запись/чтение/закрытие), планировщик Go проверяет ожидающие горутины
    - Одна из ожидающих горутин выбирается для пробуждения (случайным образом, если их несколько)
    - Пробужденная горутина получает возможность выполнить соответствующий case

## Защита от race conditions

Go обеспечивает атомарность операций с каналами через:

1. **Мьютексы каналов**:
    - Каждый канал имеет свой внутренний мьютекс
    - Операции с каналом защищены этим мьютексом

2. **Атомарность select**:
    - Когда горутина просыпается, она атомарно проверяет возможность выполнения операции
    - Если другой горутина "опередила" и выполнила операцию, текущая горутина снова блокируется

## Пример с race condition

```go
ch := make(chan int, 1)
ch <- 1 // Записываем одно значение

go func() {
    select {
    case v := <-ch:
        fmt.Println("Горутина 1 получила:", v)
    }
}()

go func() {
    select {
    case v := <-ch:
        fmt.Println("Горутина 2 получила:", v)
    }
}()
```

В этом случае:
1. Обе горутины регистрируются на чтение из канала
2. Только одна из них получит значение (выбирается случайно)
3. Вторая горутина останется заблокированной (если нет default case)

## Как select обрабатывает конкуренцию

1. **Порядок проверки case-ов**:
    - Go перебирает case-ы в случайном порядке (специально перемешивает)
    - Это предотвращает голодание (starvation) определенных case-ов

2. **Non-blocking операции**:
    - Если канал закрыт, соответствующий case выполняется немедленно
    - Если в канале есть данные (для чтения) или место (для записи), case может выполниться

3. **Default case**:
    - Если добавлен `default`, select не блокируется, а сразу выполняет default, если ни один канал не готов

## Реализация в рантайме

На низком уровне это работает так:
1. Создается структура `scase` для каждого case
2. Вызывается `selectgo()` (функция рантайма), которая:
    - Перемешивает case-ы
    - Проверяет готовые каналы
    - Регистрирует ожидание в неготовых каналах
    - Паркует горутину, если нужно
    - Разблокирует при наступлении события

## Пример с защитой от race

```go
ch := make(chan int)
var mu sync.Mutex
var value int

go func() {
    mu.Lock()
    defer mu.Unlock()
    select {
    case ch <- 1:
        value = 1
    default:
        value = -1
    }
}()

go func() {
    mu.Lock()
    defer mu.Unlock()
    select {
    case v := <-ch:
        value = v
    default:
        value = -2
    }
}()
```

В этом примере мьютекс защищает не только доступ к `value`, но и обеспечивает последовательный доступ к операциям с каналом.

Таким образом, механизм select в Go обеспечивает:
- Справедливое распределение между case-ами
- Защиту от race conditions
- Эффективную блокировку и пробуждение горутин
