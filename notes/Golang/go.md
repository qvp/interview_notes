# Golang

## Как выполняется Go
<!-- junior 3525480 -->
Golang - компилируемый язык. Его инструменты преобразуют исходный текст программы, а также библиотеки, от которых он зависит, в команды на машинном языке компьютера.

## Почему Go быстрее Python
<!-- junior 3525480 -->
Python компилируется в байт-код, который затем выполняется виртуальной машиной (CPython).  
Байт-код - это промежуточное представление, которое интерпретируется построчно (хотя и с оптимизациями).  
Динамическая типизация требует проверки типов в runtime, что замедляет выполнение.  
GIL мешает настоящему параллелизму (только один поток исполняется в один момент).  
Сборщик мусора (GC) работает непредсказуемо и может вызывать задержки.  
Минимум оптимизаций (т.к. код может измениться в runtime через метаклассы, monkey patching и.т.д.).  
Динамическая диспетчеризация — каждый вызов метода требует поиска в словаре.  
Много высокоуровневых абстракций (list, dict), которые удобны, но не всегда оптимальны.  
Большая часть библиотек написана на C (например, json, re), но вызовы из Python добавляют накладные расходы.  

Go компилируется прямо в машинный код (без виртуальной машины).  
Исполнение происходит нативно, без дополнительного слоя интерпретации.  
Статическая типизация позволяет оптимизировать код на этапе компиляции.  
Нет GIL, есть легковесные потоки (горутины), работающие поверх системных тредов.  
Более эффективный GC (неблокирующий, с низкими паузами).  
Память выделяется стэками горутин, что уменьшает нагрузку на кучу.  
Статическая компиляция позволяет проводить агрессивные оптимизации (инлайнинг, dead code elimination и др.).  
Прямые вызовы функций (без lookup-таблиц, как в Python).  
Библиотеки (сети, криптография, парсинг) оптимизированы под скорость.  
****  
| Фактор              | Python                          | Go                              |
|---------------------|--------------------------------|--------------------------------|
| **Исполнение**       | Интерпретация байт-кода        | Нативный машинный код          |
| **Типизация**        | Динамическая (проверки в runtime) | Статическая (оптимизация при компиляции) |
| **Параллелизм**      | GIL (почти нет многопоточности) | Горутины (реальный параллелизм) |
| **Управление памятью** | Reference counting + GC с паузами | Эффективный неблокирующий GC   |
| **Оптимизации**      | Минимум (динамизм мешает)      | Агрессивные (инлайнинг, удаление мёртвого кода) |

## Пакет
<!-- junior 3525480 -->
Код программы организован в виде пакетов, которые подобны библиотекам или модулям других языков.

Пакеты служат для поддержки модульности, инкапсуляции, раздельной компиляции и повторное использование.

Пакет состоит из одного или нескольких файлов исходного кода в одном каталоге.

Пакет `main` особый, он определяет отдельную программу, а не библиотеку. В пакете `main` функция `main` тоже является особой - именно с нее начинается программа.

Инициализация файлов в пакете происходит в алфавитном порядке.

Они вызываются автоматически в том порядке в котором объявлены.

## Область видимости
<!-- junior 3525480 -->
Если некая сущность объявлена внутри функции, то она является локальной.  
Каждая сущность уровня пакета видна не только в исходном файле, но и во всех файлах пакета.  
Если сущность объявлена с заглавной буквы, то она видна за границами пакета.  
Переменная объявленная внутри лексического блока видна только в этом блоке (for, if, switch, case).  

Начиная с Go 1.22, для циклов for с range (и обычных for i := 0; i < N; i++) каждая итерация создаёт новую переменную. Это значит, что замыкания внутри цикла захватывают уникальную копию переменной для своей итерации, и проблема исчезает.

## Указатель
<!-- junior 3525480 -->
Это адрес переменной. Не всякое значение имеет адрес, но его имеет любая переменная. С помощью указателя можно считывать или изменять значение переменной косвенно (не используя или даже не зная ее имя).

```go
x := 1
p := &x // p имеет тип *int и указывает на x
fmt.Println(*p) // 1
*p = 2
fmt.Println(x) // 2
*p++ // увеличивает значение, на которое указывает p но не изменяет p
// *p это псевдоним x
```
Нулевое значение указателя `nil`.  

Оператор `&` возвращает указатель для значения.  

Оператор `*` позволяет задать либо вернуть значение по указателю.  

## Указатель на указатель
<!-- junior 3525480 -->
Это переменная, которая хранит адрес памяти другого указателя. Он не только позволяет нам получить доступ к значению a через двойное разыменование (**c), но и изменять адрес, на который указывает b.
```go
a := 1
b := &a
var c **int = &b
var d ***int = &c // print d: 0xc00008e068
```

Минус указателей - код становится сложнее понять.

## Type Assertion
<!-- junior 3525480 -->
Декларация или утверждение типа. Представляет собой операцию, применяемую к значению-интерфейсу. Она проверяет, что динамический тип соответствует декларируемому типу. Применяется только к интерфейсам.
```go
value, ok := интерфейс.(Тип) // безопасная форма
value := интерфейс.(Тип)    // небезопасная форма (может вызвать panic)
```

## Type Conversion
<!-- junior 3525480 -->
Приведение типов. Это механизм явного преобразования значения одного типа в другой, когда такое преобразование разрешено правилами языка.
```go
s := "hello"

s2 := string(b) // обратное преобразование

```

## Type Switch
<!-- junior 3525480 -->
Это специальная конструкция в Go, позволяющая определить динамический тип интерфейса и выполнить разные действия в зависимости от этого типа.  
Это мощный инструмент для работы с интерфейсами и пустыми интерфейсами (interface{}).  
```go
func printType(i interface{}) {
    switch v := i.(type) {
    case int:
        fmt.Printf("Это целое число: %v\n", v)
    case string:
        fmt.Printf("Это строка: %v\n", v)
    case bool:
        fmt.Printf("Это булево значение: %v\n", v)
    default:
        fmt.Printf("Неизвестный тип: %T\n", v)
    }
}
```
Type switch проверяет сразу несколько типов.  
В каждой ветке case переменная v имеет соответствующий тип.  
Можно использовать это для безопасного доступа к методам типа.  
Делает код более читаемым и безопасным по сравнению с цепочкой if-else с type assertions.

## Локальные переменные (стековые)
<!-- junior 3525480 -->
Объявлены внутри блока кода (функции, условия, цикла, switch, select) и продолжают существовать до выхода из него. Память обычно выделяется на стеке (если компилятор не решит иначе).
```go
func foo() {
    x := 10  // Локальная переменная
    println(x)
}
// x перестаёт существовать здесь
```

## Динамические переменные (куча)
<!-- junior 3525480 -->
Существуют до тех пор, пока есть ссылки на переменную (управляется сборщиком мусора). Память выделяется в куче, если переменная "убегает" (escapes) из текущей области видимости.
```go
func bar() *int {
    y := 20  // Может быть выделено в куче (escape analysis)
    return &y
}
```

## Глобальные переменные
<!-- junior 3525480 -->
Объявляется вне функций. Доступна на протяжении жизни программы. Обязательно начинается с `var` или `const`. Память выделяется в статической памяти или куче.

**Параметры и возвращаемые значения**  
Время жизни зависит от использования вызывающим кодом.
```go
func sum(a, b int) (result int) {
    result = a + b
    return  // result существует после return, пока используется вызывающей стороной
}
```

## Escape Analysis
<!-- junior 3525480 -->
Escape Analysis - компилятор решает, выделять память на стеке или в куче. Если адрес переменной "убегает" из функции (например, возвращается или сохраняется в глобальную переменную), она размещается в куче.
Сборка мусора автоматически освобождает память, когда объекты больше не нужны.

```go
func main() {
    p := createPointer()
    println(*p)
}

func createPointer() *int {
    v := 42
    return &v  // v "убегает" в кучу, так как возвращается указатель
}
```

## Var overflow
<!-- junior 3525480 -->
Может происходить переполнение переменных (overflow), когда значение превышает максимально возможное для данного типа данных.

## new
<!-- junior 3525480 -->
Используется для выделения памяти под новое значение указанного типа и возвращает указатель на это значение.  
Переменная созданная с помощью `new`, ничем не отличается от обычной локальной переменной, у которой берется адрес. Конструкция `new` является лишь синтаксическим удобством, чтобы не создавать новую переменную если нужно лишь вернуть указатель на нее.  
Каждый вызов возвращает отличную от предыдущих переменную с уникальным адресом. Исключение составляют две переменные, тип которых не несет никакой информации: `struct{}` и `[0]int` они могут иметь один и тот же адрес в зависимости от реализации.
В большинстве случаев в Go предпочитают использовать литералы (`&T{}`) вместо new, так как это более читаемо.

## String
<!-- junior 3525480 -->
Строки в Go — это неизменяемые массивы байт в UTF-8. Для работы с Unicode нужно использовать rune. Операции со строками могут создавать новые объекты, но компилятор старается оптимизировать работу с ними.  
`len` возвращает количество байтов, а не символов.  
`s[i]` возвращает i-й байт в строке.  
`utf8.RuneCountInString(s)` возвращает количество рун в строке.  

i-й байт строки не обязательно является i-м символом строки, поскольку кодировка UTF-8 символов, не являющихся символами ASCII, требует двух и более байтов. 

Строка - это структура, которая содержит указатель на массив байт и длину:
```go
type stringStruct struct {
    str unsafe.Pointer // указатель на массив байт
    len int           // длина строки в байтах
}
```
`range` неявно приводит байты к рунам:
```go
// Итерация по символам
for index, ch := range "тест" {
    fmt.Println(index, ch, string(ch)) // 0 1090 т
    fmt.Printf("%c ", ch) // т
}
```

## Значимые и ссылочные типы
<!-- junior 3525480 -->

## Значимые типы (Value Types)
<!-- junior 3525480 -->
При присваивании или передаче в функцию копируется всё значение.  
`int`, `float64`, `complex128`, `bool`, `string`, `byte`, `rune`, `struct`, `array`

## Ссылочные типы (Reference Types)
<!-- junior 3525480 -->
При присваивании или передаче в функцию копируется только указатель на данные, но не сами данные.  
`slice`, `map`, `channel`, `pointer`, `func` (если передаются как значения)

Интерфейсы это особый случай - они хранят динамическое значение и тип, и их поведение зависит от того, что в них хранится:
Если в интерфейс помещён значимый тип, то при присваивании копируется значение.
Если в интерфейс помещён ссылочный тип, то копируется ссылка.

## goto

```go
    }
```

## Runtime
<!-- junior 3525480 -->
Это часть исполняющей среды языка, которая предоставляет ключевые функции во время выполнения программы (а не во время компиляции).  

Runtime в Go - это коллекция функций и сервисов, которые:
* Управляют памятью (сборка мусора)
* Обеспечивают работу горутин (легковесных потоков)
* Обрабатывают системные вызовы
* Управляют планированием горутин
* Обеспечивают рефлексию (reflect)
* Обрабатывают паники (panic/recover)
```go
runtime.GC() // Принудительный вызов GC
runtime.GOMAXPROCS(4) // Установка максимального количества процессоров
num := runtime.NumGoroutine() // Узнать количество горутин
runtime.Gosched() // Принудительно передать управление другой горутине ???
runtime.SetMaxStack(1 << 20) // // Увеличение размера стека до 1MB
runtime.newobject() // выделяет память в куче
```

## Экономия памяти
<!-- junior 3525480 -->
1. Избегать глобальных переменных: глобальные переменные остаются в памяти на протяжении всего времени выполнения программы. Используйте их, когда это действительно необходимо.
2. Использовать правильные типы данных: например, вместо использования int для небольших чисел можно использовать int8/int16 и т. д., в зависимости от диапазона значений.
sync.Pool: если в программе часто создаются и удаляются большие объекты, мы можем использовать sync.Pool для их повторного использования.
3. Ленивая инициализация: инициализировать сложные структуры данных или большие массивы желательно только тогда, когда они действительно нужны.
4. Использовать указатели на структуры: вместо передачи копии структуры мы можем передать указатель на нее. Важно знать, что это правило работает не всегда и не везде (подробнее можно прочитать здесь).
5. Срезы vs массивы: срезы могут менять свой размер и динамически выделять память. Если размер данных известен, лучше использовать массив.
6. Освобождать ресурсы: временные большие структуры данных, которые больше не нужны, следует явно освобождать, присваивая им значение nil, чтобы сборщик мусора мог быстрее их убрать.
7. Использовать буферизацию: буферизированный ввод/вывод или буферизированные каналы могут сократить количество выделений и освобождений памяти.
8. Оптимизировать структуры: структуры в Go выровнены по памяти. Переупорядочивание полей структуры может уменьшить ее размер.

## Затенённые переменные
<!-- junior 3525480 -->
В Go затенённая переменная (variable shadowing) возникает, когда вы объявляете новую переменную с тем же именем, что и переменная из внешней области видимости, "затеняя" первоначальную переменную.

golang.org/x/tools/go/analysis/passes/shadow/cmd/shadow  
`go vet -vettool=$(which shadow)`  

```go
x := 10

if true {
    // внутри блока можно создать новую переменную с тем же именем
    x := 20 // Это новая переменная, затеняющая внешнюю x
    fmt.Println(x) // Выведет: 20
}

x := 0 // в том же блоке повторно создать переменную нельзя
fmt.Println(x) // Выведет: 10 (внешняя x не изменилась)
```
