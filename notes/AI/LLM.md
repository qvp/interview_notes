# Large Language Model

## Что такое LLM
Large Language Model - это большая языковая модель, основанная на искусственном интеллекте, способная понимать, генерировать и обрабатывать человеческий язык.  
Модель обучается на текстах из интернета, книг, статей и других источников (например, GPT-3 обучалась на сотнях миллиардов слов).  
Она изучает статистические закономерности языка: какие слова чаще следуют друг за другом, как строятся предложения и.т.д.  
LLM — мощный инструмент, но это не «искусственный разум», а сложная статистическая модель языка.  

## Предсказание следующего слова
Когда вы задаете вопрос, модель предсказывает наиболее вероятные продолжения текста, учитывая контекст.  
Она не «понимает» смысл в человеческом смысле, а вычисляет вероятности на основе данных.  

## Что умеют LLM
* Отвечать на вопросы
* Писать код, статьи, стихи
* Переводить языки
* Анализировать и обобщать текст
* Поддерживать диалог

## Ограничения LLM
* Могут выдавать ложную информацию (галлюцинации)
* Не имеют реального понимания мира
* Зависят от качества обучающих данных

## Токен
Это минимальная единица текста, которую языковая модель (например, GPT) обрабатывает.

Это может быть:
* Одно слово (например, "кошка" → 1 токен).
* Часть слова (например, "бегемот" → может разбиться на "бег", "ем", "от" → 3 токена).
* Символ или знак препинания (например, "!" → 1 токен).

Токены ≠ буквы. Одно слово на русском обычно = 1–3 токена, на английском — 1–2 токена.  
"ChatGPT" → "Chat" + "G" + "PT" → 3 токена  
"Привет!" → "Привет" + "!" → 2 токена

В API платных моделей (например, OpenAI) billing идет за токены.   
У моделей есть лимит на входные токены (например, GPT-4 Turbo поддерживает 128K токенов).  

Чтобы узнать сколько токенов в тексте можно воспользоваться онлайн инструментами или написать свою программу.  
https://platform.openai.com/tokenizer

## Декодер

## Трансформер
Это архитектура нейронных сетей, разработанная в 2017 году. Они лежат в основе современных LLM (GPT, BERT, Claude и др.) и позволяют эффективно обрабатывать последовательности (текст, речь, код).
Ключевая идея: отказ от рекуррентных (RNN) и сверточных (CNN) сетей в пользу механизма внимания (attention), который анализирует связи между всеми словами сразу.  

Трансформер представляет собой многослойную нейросеть. На каждом слое работает механизм внимания (Self-Attention), который анализирует контекстные связи между словами.

## Механизм внимания
Помогает машине определить, какие слова в предложении самые важные для понимания смысла.

Каждое слово соотносится с другими словами и им присваиваются балы внимания относительно этого слова.

Присвоив словам баллы внимания, модель использует их для корректировки влияния (или «веса») каждого из них. Слова с более высокими баллами внимания вносят больший вклад в выявление смысла предложения.

## Обучение LLM
Процесс обучения делится на две основных стадии: предобучение (предварительное обучение) и файн-тюнинг (дообучение).

Предварительное обучение — это начальная стадия, когда большая языковая модель обучается на широком и разнообразном наборе данных, благодаря чему выявляет общие языковые шаблоны, структуры и семантику.

## RAG Персонализация контента
Маркетинговые команды с помощью RAG могут создавать персонализированный контент для рассылок по электронной почте, публикаций в социальных сетях и описания продуктов на основе соответствующей информации о клиентах,
истории взаимодействия с ними и каталогов продукции. Благодаря мгновенному получению и включению в маркетинговые материалы конкретных данных или предпочтений клиентов.

## Гиперпараметры
Это настройки, которые определяют, как именно модель будет генерировать текст во время работы (инференса) или как она будет обучаться.

Гиперпараметры инференса (или генерации):
- Temperature Контролирует «креативность» и «случайность» ответов.
- Top-p (или Nucleus Sampling / Ядерная выборка) Альтернативный способ контроля разнообразия. Он ограничивает выбор модели не температурой, а набором слов.
- Top-k Еще более простой способ ограничить выборку. Модель рассматривает только k самых вероятных следующих слов и выбирает из них.
- Max Length Просто ограничивает количество токенов (слов или их частей) в ответе, чтобы модель не генерировала бесконечно.
- Stop Sequences (Стоп-последовательности) Набор символов или слов, при появлении которых модель должна остановить генерацию.

Гиперпараметры обучения (тренировки):
- Learning Rate (Скорость обучения / Шаг обучения) Определяет, насколько сильно модель будет меняться после каждой порции данных.
- Batch Size (Размер пакета) Количество примеров, которые модель обрабатывает за один раз, прежде чем обновить свои знания.
- Количество слоев (Layers) и Размерность (Hidden Size) Это параметры архитектуры нейросети. Они определяют «физический» размер мозга модели. 

## Text Generation
Это процесс предсказания последовательности слов на основе входных данных.

Основные этапы генерации текста:
* Токенизация входного промта
* Обработка через трансформер
* Предсказание следующего токена
* Выбор следующего слова
* Постепенная генерация (Autoregressive)
* Остановка генерации

## Выбор следующего слова
Модель выбирает токен одним из методов:
* Жадный поиск (Greedy Search): Берётся токен с максимальной вероятностью. Быстро, но ответы могут быть шаблонными.
* Сэмплирование (Sampling): Токен выбирается случайно, но с учётом вероятностей. Креативно, но может выдавать ошибки.

## Что влияет на качество генерации
1. Температура (`Temperature`)
    * `Temperature=0` → детерминированный режим (всегда выбирает самый вероятный токен).
    * `Temperature=1` → баланс между креативностью и точностью.
    * `Temperature>1` → больше случайности (может выдавать бессмыслицу).

2. Параметры сэмплирования (`top-k`, `top-p`)
    * Чем уже диапазон (top-k=10, top-p=0.5), тем более предсказуем текст.

3. Повторяемость (`Repetition Penalty`)
    * Штрафует модель за повторение одних и тех же фраз.

4. Контекстное окно
    * Чем больше токенов "помнит" модель (например, 128K у GPT-4 Turbo), тем связнее длинные тексты.

## Промптинг
Это запрос к языковой модели.  

Основные приемы:
* Продолжение текста
* zero shot
* one shot
* few shot
* Chain-of-thought
* Self-consistency
* Generated Knowledge Prompting
* Retrieval augmented generation (RAG)

Методы улучшения результата генерации:
1. Назначение роли. Задавать контекст модели можно с помощью назначения ей определенной роли. Например: «Ты — туристический гид», или «Ты — редактор».
2. Четкие инструкции. Качество ответов повышает четкая формулировка формата, стиля или необходимых для выполнения задачи шагов.
3. Определение последовательности. Разбиение сложной подсказки на последовательность более простых подсказок.
4. Обучение с небольшим количеством примеров (few-shot learning). Включение в запрос примеров, на основе которых модель должна построить свой ответ.

## LangChain
Создание цепочек (chains) и агентов (agents) для сложных workflow с LLM.

LangChain может помочь если нужно:  
* Работать с документами (PDF, сайтами, базами данных).
* Сохранять историю диалога (чат-бот с памятью).
* Вызывать внешние инструменты (поиск в Google, вычисления в Python).
* Строить сложные цепочки действий (анализ → генерация → проверка).

## Ограничения LangChain
LangChain упрощает работу со сложными пайплайнами (например, RAG или агенты), но добавляет накладные расходы и снижает гибкость по сравнению с прямым API. Он удобен для быстрого прототипирования, но для простых задач или максимального контроля лучше использовать прямое взаимодействие с LLM. Выбор зависит от сложности сценария и требований к производительности.

## Retrievers
Это компоненты систем, которые работают вместе с большими языковыми моделями (LLM), чтобы находить и извлекать релевантную информацию из внешних источников (например, баз данных, документов или поисковых систем). Они решают проблему ограниченных знаний LLM, позволяя модели обращаться к актуальным или специализированным данным без необходимости хранить всё в своих параметрах.

Они решают следующие задачи:
* **Расширение контекста LLM** - LLM обладают знаниями только на момент их обучения. Retriever может подтягивать свежие или приватные данные. Например, последние новости.
* **Работа с большими объемами данных** - LLM имеют ограничение на длину контекста (например, 128K токенов у GPT-4 Turbo). Retriever выбирает только нужные фрагменты, чтобы не перегружать модель.
* **Точность ответов** - Вместо генерации "из головы" (риск галлюцинаций), LLM получает факты из проверенных источников.
* **Специализированные знания** - Например, медицинский чатбот может искать информацию в научных статьях или базах данных.

Как работают ретрейверы
* **Векторный поиск** - Текст (запрос пользователя или документы) преобразуется в векторные embedding. Похожие векторы находятся через алгоритмы вроде FAISS, Annoy или Pinecone (базы данных для векторного поиска).
* **Гибридные методы** - Комбинируют семантический поиск (по смыслу) и ключевые слова (как в традиционном поиске).
* **RAG** - Retriever передает LLM найденные документы как контекст, и модель генерирует ответ на их основе.

Примеры использования
* **Вопрос-ответные системы** - Пользователь спрашивает: "Какие новые функции в Python 3.12?" → Retriever находит документацию → LLM резюмирует её.
* **Поддержка клиентов** - Поиск в базе FAQ или мануалах перед генерацией ответа.
* **Анализ документов** - Юридический ассистент ищет прецеденты в судебных базах данных.

## Embedding
Embeddings (векторные представления, эмбеддинги) — это числовые векторы, которые кодируют смысл текста (слов, предложений или документов) в форме, понятной для машин. В контексте LLM они позволяют сравнивать и анализировать текстовые данные на основе их семантического сходства, а не просто по ключевым словам.

В отличие от необработанных векторов, эмбеддинги отражают семантические отношения между токенами. Это значит, что токены с похожими значениями будут иметь похожие эмбеддинги, даже если встречаются в разных контекстах.

Какую задачу решают эмбеддинги
* **Сравнение текстов по смыслу** - Позволяют находить похожие фразы, даже если они не содержат одинаковых слов. Пример: Запрос "Как приготовить пасту?" и документ "Рецепт итальянских макарон" будут близки в векторном пространстве.
* **Поиск информации (Retrieval)** - Основа для работы RAG (Retrieval-Augmented Generation) — retriever ищет документы по их эмбеддингам.
* **Кластеризация и классификация** - Группировка похожих отзывов, новостей или запросов.
* **Уменьшение размерности данных** - Текст преобразуется в компактный вектор (например, 768 или 1536 чисел), с которым легче работать, чем с raw-текстом.

Для создания эмбеддингов используются специальные embedding модели, а не большие языковые модели (LLM) вроде GPT. Схожие по теме документы имеют схожие векторы. В векторной БД есть поиск схожих документов.  

Векторы рассчитываются относительно семантического пространства, изученного моделью во время тренировки. При смене модели ВСЕ векторы становятся другими и несравнимыми. Для векторизации и поиска по вектору нужна одна и та же модель, но LLM обрабатывающая результаты поиска может быть другая.

Благодаря эмбеддингам LLM получают своего рода представление о языке, что позволяет им выполнять такие задачи, как анализ настроения, резюмирование текста и ответы на вопросы с нужным уровнем точности.

## Приближенный поиск
(Approximate Nearest Neighbors, ANN) - это методы быстрого поиска похожих векторов в больших наборах данных, когда точный поиск становится слишком медленным. Вместо полного перебора всех вариантов (как в точном поиске), ANN жертвует небольшой долей точности ради значительного ускорения.

## Agents
Это продвинутые системы на основе LLM (например, GPT-4, Claude, Gemini), которые умеют автономно выполнять задачи, используя внешние инструменты, API и внутренние рассуждения. Они действуют как "виртуальные ассистенты", способные планировать, принимать решения и взаимодействовать с окружением.

Зачем нужны агенты
* **Решение сложных задач** - Обычные LLM отвечают на один запрос за раз. Агенты разбивают задачу на шаги, анализируют промежуточные результаты и корректируют действия.
* **Работа с внешними API** - Агенты интегрируются с базами данных, поисковыми системами (Google), калькуляторами, соцсетями и т.д.
* **Автоматизация процессов** - Подходят для чат-ботов поддержки, аналитики данных, управления умным домом.

Архитектура агента состоит из четырех основных компонентов:
1. Мозг. Ядро агента, обычно LLM, действующая как центр принятия решений.
2. Планировщик. Этот компонент разбивает сложные задачи на управляемые шаги.
3. Память. Агент сохраняет контекст и информацию для последующего использования, помогая поддерживать непрерывность.
4. Инструменты. Агент использует различные инструменты, осуществляющие вызовы API, запросы к базе данных и даже создающие программный код для выполнения указанных пользователем задач.

## Контекстное окно
Это фиксированное количество токенов, которые модель может учитывать при генерации ответа.
Контекстное окно (например, 4K, 8K, 32K, 128K токенов в разных моделях) — это "оперативная память" модели, куда попадают все предыдущие сообщения диалога.  
Каждый новый запрос добавляется в контекст вместе с историей, и модель генерирует ответ, учитывая весь накопленный текст.  
Если контекст переполняется, самые старые сообщения "забываются" (вытесняются из окна).  

Как продолжить тему и задавать вопросы в контексте
* **Передавать историю диалога явно** - Каждое новое сообщение должно включать предыдущие вопросы и ответы.
* **Использовать API с поддержкой сессий** - Некоторые API (например, OpenAI ChatGPT) автоматически поддерживают сессионную память в рамках одного чата.
* **Сжимать или суммировать контекст**
* **Явно ссылаться на прошлые ответы**

## Model Style
Completion Style - Модель получает на вход начало текста (промпт) и ее задача — продолжить его наиболее вероятным с точки зрения ее тренировочных данных способом.

Chat Style - Модель получает на вход структурированный диалог, состоящий из ролей (обычно system, user, assistant), и ее задача — сгенерировать ответ, который был бы уместен в данном контексте разговора.

На практике сегодня, для большинства задач с современными моделями, рекомендуется начинать с Chat Style, так как он более гибкий и интуитивно понятный. Completion Style остается нишевым, но критически важным инструментом для конкретных сценариев, таких как автодополнение кода.

## Memory
Это механизм для сохранения состояния (контекста) между вызовами языковой модели (LLM) который позволяет приложениям с ИИ "помнить" информацию из предыдущих взаимодействий.

Создаётся итоговый промпт, который включает: контекст из памяти + ваш исходный запрос.

Есть разные стратегии хранения истории: целиком, последние n-сообщений, резюмированную, память сущностей (Conversation Entity).
