# Паттерны

## ActiveRecord
Объект является "обёрткой" одной строки из БД или представления, включает в себя доступ к БД и логику обращения с данными.

Если в моделе содержится бизнес логика, то нарушается принцип единственной ответственности (SRP), совмещая в одном объекте как представление и внутреннюю логику самого объекта, так и механизмы CRUD, поэтому Active Record может считаться антипаттерном.

Используется например в Django ORM

## Data Mapper
(Преобразователь данных) осуществляет передачу данных между объектами и базой данных, сохраняя части независимыми друг от друга и от самого преобразователя.

Бизнес логика и логика сохранения данных слабо связанны. Принцип SRP не нарушается.

Используется например в SqlAlchemy ORM.

## Repository
Репозиторий - это слой абстракции, инкапсулирующий в себе всё, что относится к способу хранения данных.  
Назначение: Разделение бизнес-логики от деталей реализации слоя доступа к данным.

Применение данного паттерна не предполагает создание только одного объекта репозитория во всем приложении. Хорошей практикой считается создание отдельных репозиториев для каждого бизнес-объекта или контекста, например: OrdersRepository, UsersRepository, AdminRepository.

## Service Layer
Инкапсулирует бизнес логику приложения. Для повторного ее использования.

## Service object
Инкапсулирует бизнес-логику приложения в отдельные классы, упрощая поддержку и тестирование кода.

## Unit of Work
Реализация паттерна Unit of Work следит за всеми действиями приложения, которые могут изменить БД в рамках одного бизнес-действия. Когда бизнес-действие завершается, Unit of Work выявляет все изменения и вносит их в БД.

## Inversion of Control (IoC)
Это некий абстрактный принцип, набор рекомендаций для написания слабо связанного кода. Суть которого в том, что каждый компонент системы должен быть как можно более изолированным от других, не полагаясь в своей работе на детали конкретной реализации других компонентов.

Реализации:
- Dependency Injection
- Service Locator
- Template Method
- Strategy
- Event-Driven / Callbacks
- Factory Method
- Observer Pattern
- Plugin Architecture
- Dependency Lookup
- Aspect-Oriented Programming

## Dependency Injection (DI)
Конкретная реализация IoC, где зависимости передаются объекту извне, а не создаются внутри него.

FastAPI имеет мощную встроенную систему DI через Depends().  
Django не имеет встроенного DI.  
Python библиотека dependency_injector.

✅Гибкость - можно менять реализации без изменения основного кода.  
✅Тестируемость - легко подменять зависимости mock-объектами.  
✅Повторное использование - компоненты становятся более универсальными.  
✅Упрощение конфигурации - зависимости настраиваются в одном месте.  
❌Сложность реализации.  
❌Снижение читаемости кода.  
❌Проблемы с циклическими зависимостями.  
❌Усложнение отладки.  
❌Производительность.  
❌Проблемы со статическим анализом.
