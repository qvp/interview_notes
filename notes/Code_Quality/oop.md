# ООП

## Что такое ООП
Объектно-ориентированное программирование (ООП) — это парадигма программирования, основанная на концепции объектов, которые содержат данные и методы для работы с этими данными. Основные понятия ООП включают:

## Класс (Class)
- Это шаблон или описание для создания объектов. Класс определяет свойства (атрибуты) и методы (функции), которые будут доступны объектам этого класса.
- Пример: класс `Car` может иметь атрибуты `color`, `speed` и методы `accelerate()`, `brake()`.

## Объект (Object)
- Это экземпляр класса. Объект создается на основе класса и содержит конкретные данные.
- Пример: объект `myCar` класса `Car` может иметь цвет "красный" и скорость 100 км/ч.

## Инкапсуляция (Encapsulation)
- Это принцип, который объединяет данные и методы, работающие с этими данными, в одном объекте. Инкапсуляция также позволяет скрывать внутренние детали реализации от внешнего мира, используя модификаторы доступа (например, `private`, `protected`, `public`).
- Пример: атрибут `speed` может быть скрыт (private), а доступ к нему осуществляется через методы `getSpeed()` и `setSpeed()`.

## Наследование (Inheritance)
- Это механизм, позволяющий создавать новый класс на основе существующего. Новый класс (подкласс) наследует свойства и методы родительского класса (суперкласса) и может добавлять свои собственные.
- Пример: класс `ElectricCar` может наследовать от класса `Car` и добавлять новый атрибут `batteryCapacity`.

## Полиморфизм (Polymorphism)
- Это возможность объектов разных классов использовать методы с одинаковыми именами, но разной реализацией. Полиморфизм позволяет работать с объектами разных классов через общий интерфейс.
- Пример: метод `accelerate()` может быть реализован по-разному в классах `Car` и `ElectricCar`.

## Абстракция (Abstraction)
- Это процесс выделения основных характеристик объекта, игнорируя несущественные детали. Абстракция позволяет сосредоточиться на том, что объект делает, а не на том, как он это делает.
- Пример: класс `Vehicle` может быть абстрактным и содержать общие методы для всех транспортных средств, такие как `move()`.

## Интерфейс (Interface)
- Это контракт, который определяет набор методов, которые должны быть реализованы в классе. Интерфейсы используются для достижения полиморфизма и абстракции.
- Пример: интерфейс `Drivable` может содержать метод `drive()`, который должен быть реализован в классах `Car` и `Bicycle`.

## Ассоциация (Association)
- Это связь между объектами, которая показывает, как они взаимодействуют друг с другом. Ассоциация может быть однонаправленной или двунаправленной.
- Пример: класс `Driver` может быть связан с классом `Car`, так как водитель управляет автомобилем.

## Агрегация (Aggregation)
- Это частный случай ассоциации, где один объект является частью другого, но может существовать независимо.
- Пример: класс `Library` может содержать объекты класса `Book`, но книги могут существовать и без библиотеки.

## Композиция (Composition)
- Это более строгая форма агрегации, где объект-часть не может существовать без объекта-целого.
- Пример: класс `House` может содержать объекты класса `Room`, но комнаты не могут существовать без дома.

Эти понятия являются основой ООП и помогают создавать структурированные, модульные и легко поддерживаемые программы.
