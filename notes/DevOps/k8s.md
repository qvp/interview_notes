## Multi stage
<!-- middle 3525480 -->
Многоэтапный процесс сборки. При этом сначала создается промежуточный контейнер, содержащий все, что требуется для сборки программы, а затем — окончательный контейнер, в котором есть все, что требуется для ее запуска.
```dockerfile
FROM openjdk:11 AS buildstage
#...
COPY --from=buildstage /app/Hello.class /app/
```
Промежуточный первый контейнер, с помощью которого выполняется компиляция приложения, удаляется по завершении процесса компиляции (строго говоря, он сохраняется в кэше платформы Docker, однако ничто из его содержимого не добавляется в окончательный образ контейнера, используемый в продуктивной среде).

## Кластер Kubernetes
<!-- middle 3525480 -->
Кластер Kubernetes — это набор узлов, представляющих собой те вычислительные мощности, на которых запускаются контейнеры. Обычно это виртуальные машины, однако могут использоваться и чисто аппаратные (невиртуализированные) машины.

На каждом из этих узлов запускается kubelet — специальный процесс системы Kubernetes, который отвечает за взаимодействие с управляющим слоем (control plane) (процессом системы Kubernetes, осуществляющим оркестрацию) и управление жизненным циклом контейнеров, запускаемых на узлах с помощью среды запуска контейнеров.

## Сервис
<!-- middle 3525480 -->
Объект Service описывает способ представления приложения, работающего в некотором наборе подов, в виде сетевого сервиса. Сервис предоставляет единый механизм адресации и распределяет нагрузку между подами.

## Commands
<!-- middle 3525480 -->
`kubectl get pods` - список подов  
`kubectl logs <pod-name>` - посмотреть логи пода  
`kubectl apply -f deployment.yaml` - применить изменения конфига  
`kubectl rollout restart deployment/timeserver` - перезапустить поды с именем timeserver  
`kubectl port-forward deploy/timeserver 8080:80` - перенаправление порта с контейнера 80 в хост 8080
