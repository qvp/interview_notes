# ClickHouse

## Что такое ClickHouse
ClickHouse - это колоночная СУБД с открытым кодом, позволяющая выполнять аналитические запросы в режиме реального времени на структурированных больших данных.

ClickHouse использует собственный диалект SQL близкий к стандартному, но содержащий различные расширения: массивы и вложенные структуры данных, функции высшего порядка, вероятностные структуры, функции для работы с URI, специализированные агрегатные функции и многое другое.
Однако при этом имеются и ограничения:
- отсутствие транзакций
- отсутствие точечных UPDATE/DELETE (есть пакетный UPDATE/DELETE)
- ограниченная поддержка синтаксиса JOIN
- строгие типы с необходимостью явного приведения
- для некоторых операций промежуточные данные должны помещаться в оперативную память
- отсутствие оконных функций
- отсутствие полноценного оптимизатора запросов точечного чтения
- присутствие ограничений в реализации некоторых функций, связанных со спецификой использования ClickHouse в Яндексе, и т. д.

## Движки баз данных
Движки баз данных обеспечивают работу с таблицами. Доступны следующие варианты:  
**Atomic** - используется по умолчанию. Он поддерживает конфигурируемые движки таблиц и диалект SQL.

**Replicated** - Движок основан на движке Atomic. Он поддерживает репликацию метаданных через журнал DDL, записываемый в ZooKeeper и выполняемый на всех репликах для данной базы данных.

**Lazy** - сохраняет таблицы только в оперативной памяти expiration_time_in_seconds через несколько секунд после последнего доступа. Может использоваться только с таблицами *Log.

**PostgreSQL** - позволяет подключаться к БД на удаленном сервере PostgreSQL. Поддерживает операции чтения и записи (запросы SELECT и INSERT) для обмена данными между ClickHouse и PostgreSQL.

**MySQL** - позволяет подключаться к базам данных на удалённом MySQL сервере и выполнять запросы INSERT и SELECT для обмена данными между ClickHouse и MySQL.

**MaterializedMySQL** - создает базу данных ClickHouse со всеми таблицами, существующими в MySQL, и всеми данными в этих таблицах (экспериментальный).

**MaterializedPostgreSQL** - создает базу данных ClickHouse с исходным дампом данных таблиц PostgreSQL и запускает процесс репликации, т.е. выполняется применение новых изменений в фоне, как эти изменения происходят в таблице PostgreSQL в удаленной базе данных PostgreSQL.

## Движки таблиц
Движки таблиц определяют особенности работы таблицы:
- Как и где хранятся данные, куда их писать и откуда читать.
- Какие запросы поддерживаются и каким образом.
- Конкурентный доступ к данным.
- Использование индексов, если есть.
- Возможно ли многопоточное выполнение запроса.
- Параметры репликации данных.  
https://clickhouse.com/docs/ru/engines/table-engines

**\*MergeTree** - Наиболее универсальные и функциональные движки таблиц для задач с высокой загрузкой. Общим свойством этих движков является быстрая вставка данных с последующей фоновой обработкой данных. Движки *MergeTree поддерживают репликацию данных (в Replicated* версиях движков), партиционирование, и другие возможности не поддержанные для других движков.

Основная идея, заложенная в основу движков семейства *MergeTree следующая. Когда у вас есть огромное количество данных, которые должны быть вставлены в таблицу, вы должны быстро записать их по частям, а затем объединить части по некоторым правилам в фоновом режиме. Этот метод намного эффективнее, чем постоянная перезапись данных в хранилище при вставке.

**\*Log** - Простые движки с минимальной функциональностью. Они наиболее эффективны, когда вам нужно быстро записать много небольших таблиц (до примерно 1 миллиона строк) и прочитать их позже целиком.

# Словари
В clickhouse словари могут иметь несколько полей значений, которые можно получить по ключу. Использовать словари с функциями проще и эффективнее, чем JOIN со справочными таблицами.
Они похожи на таблицы, но имеют свои особенности:
- ClickHouse имеет поддержку различных вариантов расположения словарей в памяти.
- Поддержка TTL – ClickHouse автоматически обновляет словари и подгружает отсутствующие значения.
- ClickHouse предоставляет несколько вариантов для описания внешних словарей — XML-файлы и DDL-запросы.
Список доступных словарей можно узнать из таблицы "system.dictionaries".

Один из популярных кейсов использования словарей в ClickHouse - это агрегация данных по странам на основе IP (v4) адресов.

## Primary key
Первичные ключи не уникальны для каждой строки в таблице. Первичный ключ таблицы определяет, как данные сортируются при записи на диск.
Каждые 8192 строки или 10 МБ данных (называемые гранулярностью индекса) создают запись в файле индекса первичного ключа.
Первичный ключ также является ключом сортировки, который представляет собой кортеж.

## Вставка значений
Каждая вставка в таблицу MergeTree вызывает создание части в хранилище. Поэтому лучше вставлять большое количество строк в пакете - десятки тысяч или даже миллионы строк одновременно.

Если нет возможности сразу вставить много строк, то можно использовать HTTP-клиент или использовать настройку async_insert, которая группирует небольшие вставки перед их вставкой в таблицу (подходит если вставка происходит часто по чуть-чуть).  
https://clickhouse.com/docs/en/operations/settings/settings#async-insert

## Formats
ClickHouse может принимать и возвращать данные в различных форматах. Формат, поддерживаемый для ввода, может использоваться для анализа данных, предоставленных INSERT, для выполнения SELECT из таблицы с файловой поддержкой, такой как File, URL или HDFS, или для чтения словаря. Формат, поддерживаемый для вывода, может использоваться для упорядочивания результатов SELECT и для выполнения операций INSERT в таблицу с файловой поддержкой.  
https://clickhouse.com/docs/en/interfaces/formats

## Update
ClickHouse в первую очередь ориентирован на большие объемы аналитических рабочих нагрузок, но в некоторых ситуациях можно изменить или удалить существующие данные. Эти операции называются «мутациями» и выполняются с помощью команды ALTER TABLE.

```sql
ALTER TABLE [db.] <table> UPDATE <column> = <expression> WHERE <filter_expr>
```
Внутри одной команды ALTER TABLE может быть несколько UPDATE через запятую, но обновление нескольких значений в одной команде UPDATE более эффективно.

```sql
ALTER TABLE clicks ON CLUSTER main_cluster
```
Мутации могут выполняться ON CLUSTER для сегментированных таблиц.

Невозможно обновить столбцы, являющиеся частью первичного ключа или ключа сортировки.

## Delete
```sql
ALTER TABLE [db.] <table> DELETE WHERE <filter_expr>
```
Мутация для удаления записей из таблицы. Так же поддерживается ON CLUSTER для удаления из сегментированных таблиц.
Чтобы удалить все данные в таблице, более эффективно использовать команду TRUNCATE TABLE. Эту команду также можно выполнить ON CLUSTER.

## Lightweight Delete
Другой вариант удаления строк - использовать команду DELETE FROM, которая называется облегченным удалением. Удаленные строки сразу помечаются как удаленные и будут автоматически отфильтровываться из всех последующих запросов, поэтому вам не придется ждать объединения частей или использовать ключевое слово FINAL. Очистка данных происходит асинхронно в фоновом режиме.

```sql
DELETE FROM [db.] table_name [ON CLUSTER cluster] [WHERE expr]
```

Эта функция доступна только для семейства движков таблиц MergeTree.

Облегченные удаления по умолчанию являются асинхронными. Установите Mutations_sync равным 1, чтобы ожидать, пока одна реплика обработает инструкцию, и установите Mutations_sync равным 2, чтобы дождаться всех реплик. Эта функция является экспериментальной и требует, чтобы вы установили для параметра allow_experimental_lightweight_delete значение true:

## JOIN
Поддерживаются все стандартные типы объединения (INNER, LEFT OUTER, RIGHT OUTER, FULL OUTER, CROSS).

ClickHouse также предоставляет дополнительные нестандартные типы SQL JOIN, полезные для аналитических рабочих нагрузок и анализа временных рядов, включая соединение ASOF.

ASOF JOIN полезен, когда вам нужно соединить записи, которые не имеют точного совпадения. Условия, поддерживаемые для ближайшего совпадения: >, >=, <, <=.

## View
Используется для реализации представлений. Не хранит данные, а хранит только указанный запрос SELECT. При чтении из таблицы, выполняет его (с удалением из запроса всех ненужных столбцов).

## Materialized view
Материализованное представление (далее МП) это по сути такая же таблица, которая хранит данные, взятые их другой таблицы. ClickHouse следит за вставкой данных в таблице-источнике и помещает их в МП в том виде, в котором вы это описываете. Это как обычное представление View, только данные хранятся на диске, а не формируются при каждом запросе.

Для работы с МП нужно отдельно создать таблицу, в которую будут присылаться данные выбранные с помощью указанного в МП запроса.

При очистке таблицы-источника данных, данные из таблицы назначения МП нужно удалять самостоятельно.

К одной таблице можно присоединить несколько МП.

Агрегация идет ТОЛЬКО на данные, которые вы вставляете в текущей пачке. То есть если вставить данные за одно и тоже время, но разными запросами, то они не просуммируются между собой. Это касается любых других агрегирующих функций в CH. Вероятно за счет таких жертв обеспечивается очень высокая скорость вставки.  
https://habr.com/ru/articles/657579/

## Live View
Хранит результат запроса SELECT, указанного при создании, и обновляется сразу же при изменении этого результата. Конечный результат запроса и промежуточные данные, из которых формируется результат, хранятся в оперативной памяти, и это обеспечивает высокую скорость обработки для повторяющихся запросов. LIVE-представления могут отправлять push-уведомления при изменении результата исходного запроса SELECT. Для этого используйте запрос WATCH.

LIVE-представления работают по тому же принципу, что и распределенные таблицы. Но вместо объединения отдельных частей данных с разных серверов, LIVE-представления объединяют уже имеющийся результат с новыми данными. Если в исходном запросе LIVE-представления есть вложенный подзапрос, его результаты не кешируются, в кеше хранится только результат основного запроса.

## TTL
TTL (time-to-live) относится к способности перемещать, удалять или сворачивать строки, или столбцы по истечении определенного интервала времени.

Хотя выражение «время жизни» звучит так, как будто оно применимо только к удалению старых данных, у TTL есть несколько вариантов использования:
- Удаление старых данных: вы можете удалять строки или столбцы через указанный интервал времени.
- Перемещение данных между дисками: через определенное время можно перемещать данные между томами хранилища - это полезно для развертывания архитектуры «горячий/теплый/холодный».
- Объединение данных: можно объединять старые данные в различные полезные агрегаты и вычисления перед их удалением.

Предложение TTL может стоять после определения столбца и/или в конце определения таблицы.

## Deduplication
Дедупликация относится к процессу удаления повторяющихся строк набора данных.
ClickHouse не проверяет существующий первичный ключ перед вставкой строки, поэтому дедупликация требует немного больше усилий.
Дедупликация реализована в ClickHouse с помощью следующих движков таблиц:
- ReplacingMergeTree: с помощью этого механизма таблицы повторяющиеся строки с одинаковым ключом сортировки удаляются во время слияния.
- CollapsingMergeTree и VersionedCollapsingMergeTree используют логику, при которой существующая строка «отменяется» и вставляется новая строка.
https://clickhouse.com/docs/en/guides/developer/deduplication

## Transaction
INSERT в один раздел в одной таблице семейства MergeTree до строк max_insert_block_size (1М по умолчанию) является транзакционным (ACID). Вставляются либо все строки либо не одной.

## Commit and Rollback
ClickHouse имеет экспериментальную поддержку транзакций, коммитов и функций отката. Чтобы они заработали нужно настроить ClickHouse Keeper или ZooKeeper для отслеживания транзакций.  
https://clickhouse.com/docs/en/guides/developer/transactional

## Партиционирование
Партиция - это набор записей в таблице, объединенных по какому-либо критерию. Например, партиция может быть по месяцу, по дню или по типу события. Данные для разных партиций хранятся отдельно. Это позволяет оптимизировать работу с данными, так как при обработке запросов будет использоваться только необходимое подмножество из всевозможных данных. Например, при получении данных за определенный месяц, ClickHouse будет считывать данные только за этот месяц.

Партиционирование данных доступно для таблиц семейства MergeTree (включая реплицированные таблицы). Таблицы MaterializedView, созданные на основе таблиц MergeTree, также поддерживают партиционирование.

Ключ партиционирования задается при создании таблицы, в секции PARTITION BY expr. Ключ может представлять собой произвольное выражение из столбцов таблицы. Например, чтобы задать партиционирования по месяцам, можно использовать выражение toYYYYMM(date_column)

## Гранулы
Каждый кусок данных логически делится на гранулы. Гранула — это минимальный неделимый набор данных, который ClickHouse считывает при выборке данных. ClickHouse не разбивает строки и значения и гранула всегда содержит целое число строк. Первая строка гранулы помечается значением первичного ключа для этой строки (засечка). Для каждого куска данных ClickHouse создаёт файл с засечками (индексный файл). Для каждого столбца, независимо от того, входит он в первичный ключ или нет, ClickHouse также сохраняет эти же засечки. Засечки используются для поиска данных напрямую в файлах столбцов.
