# Git

## cherry-pick
<!-- junior 3525480 -->
Команда git cherry-pick 3ea6207fe84 позволяет забрать один коммит из другой ветки и вставить его в текущую. В качестве параметра передаётся идентификатор коммита в другой ветке. Возмётся один коммит с идентификатором 3ea6207fe84 из той ветки, в которой он был сделан, и изменения этого коммита будут вставлены в текущую ветку как новый коммит.

## Rebase
<!-- junior 3525480 -->
Rebase - это «автоматизированный» cherry-pick. Он выполняет ту же работу, но для цепочки коммитов, тем самым как бы перенося ветку на новое место.

## Merge vs Rebase
<!-- junior 3525480 -->
Merge создаёт коммит слияния. И после merge остаются три удобных коммита. Чтобы продолжить используя только первую нить, только вторую нить, или все вместе. По сути merge создаёт историю.  
Rebase повторно применяет коммиты поверх другой базовой ветки. rebase нужен для порядка (линейность истории), чтоб потом смотреть и понимать. rebase переносит коммиты поверх того, что было в результирующей ветке. merge оставляет коммиты, как есть, просто добавляя связующий коммит между ветками.
