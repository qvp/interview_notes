# LangChain

## Chains
Это фундаментальная концепция, которая позволяет комбинировать несколько компонентов LLM-приложения в последовательные рабочие процессы. Если Tools и Agents обеспечивают гибкость и принятие решений, то Chains предоставляют структуру и предсказуемость.

Цепочка — это последовательность вызовов к LLM, инструментам или другим цепочкам, где выход одного шага становится входом для следующего.

Базовые компоненты цепочки:
* LLM — языковая модель
* Промпты — шаблоны запросов
* Tools — внешние инструменты
* Память — сохранение контекста
* Процессоры — преобразование данных

Зачем нужны цепочки:
Позволяют разбивать сложные задачи на последовательные шаги.
Каждый шаг цепочки можно отслеживать и debug-жить отдельно.
Созданные цепочки можно переиспользовать в разных проектах.

## Tolls
Это специальные утилиты (инструменты), которые позволяют языковым моделям (LLM) взаимодействовать с внешними системами и выполнять конкретные задачи, выходящие за рамки генерации текста.

Например, получить данные из бд или обработать ответ от LLM.

Каждый Tool представляет собой Python-функцию, обернутую в специальный интерфейс, который понимает модель. Этой функции присваиваются имя, описание и схема аргументов.

Процесс использования Tools агентом выглядит так:
1. Связывание (Binding): Инструменты передаются модели с помощью метода bind_tools().
2. Вызов (Calling): Модель анализирует запрос пользователя и принимает решение, какой инструмент использовать. Она возвращает сообщение с указанием имени инструмента и аргументов для вызова.
3. Исполнение (Execution): Система LangChain выполняет функцию инструмента с переданными аргументами.
4. Получение результата: Результат работы инструмента возвращается модели, которая формирует итоговый ответ пользователю.

## Memory
**ConversationBufferMemory (Память-буфер диалога)**  
Самая простая форма. Она тупо сохраняет все предыдущие сообщения в сыром виде в буфере.  
✅Простота, полный контекст.  
❌Быстро расходует токены (и деньги)

**ConversationBufferWindowMemory (Память с окном)**  
Решает проблему длинных промптов. Сохраняет только последние k взаимодействий (сообщений), а старые "забывает".  
✅Экономит токены, предотвращает "переполнение" контекста модели.  
❌Может забыть важную информацию из начала разговора.  

**ConversationSummaryMemory (Память-резюме)**  
Вместо хранения всех сообщений, она периодически (или постоянно) обращается к LLM, чтобы создать краткое текстовое резюме разговора.  
✅Очень экономно по токенам для длинных диалогов.  
❌Требует дополнительные вызовы LLM для создания резюме.  
❌Может потерять конкретные детали.  

**ConversationEntityMemory (Память сущностей)**  
Самый продвинутый и интеллектуальный тип. Она использует LLM для извлечения и запоминания ключевых сущностей (фактов) из разговора: имён, мест, дат, предпочтений и т.д. Хранит их в структурированном виде.  
✅Точечное использование контекста, очень эффективно.  
❌Сложнее в настройке.
