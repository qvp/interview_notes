## Хранение денег
Из-за проблем с точностью у цифр с плавающей точкой и накоплением ошибок существует несколько подходов со своими особенностями реализации.

### Numeric / Decimal
`amount DECIMAL(presition, scale)  -- 15 цифр всего, 4 после запятой`  
Сам по себе этот тип не накапливает ошибки, но они могут появляться при округлении если дробная часть числа имеет больше цифр после запятой чем scale (например при умножении\делении).

Плюсы:
- Точные вычисления (без ошибок округления)
- Поддержка дробных частей
- Гибкость в указании точности

Минусы:
- Медленнее integer типов (~ в 2-10 раз)
- Занимает больше места (до 16+ байт)
- Сложнее индексация
- Нужно следить за context в python

Округлениям результатов должна заниматься не БД, а бизнес логика (иначе может возникнуть ошибка из-за множественного (каскадного) округления).

Для хранения криптовалют тип Numeric не используют.

```python
from decimal import Decimal, getcontext, ROUND_HALF_UP

""" Устанавливаем точность при вычислениях """
getcontext().prec = 50  # по умолчанию 28

class Wallet(Base):
    __tablename__ = 'wallets'
    balance = Column(DECIMAL(10, 2), nullable=False, default=0)
    __table_args__ = (
        CheckConstraint('balance >= 0', name='check_balance_positive'),
        CheckConstraint('balance = ROUND(balance, 2)', name='balance_2_decimal_places'),  # Error if more than 2 decimal places
    )

value = Decimal('1.234567891')
rounded = value.quantize(  # управляет форматом результата
    Decimal('0.00000001'),  # 8 знаков
    rounding=ROUND_HALF_UP
)
```

### Integer / Bigint (центы/копейки)
`price_cents INTEGER  -- храним 100 вместо 1.00`  
Плюсы:
- Максимальная производительность
- Минимальное место (4 или 8 байт)
- Простые вычисления
- Легкая индексация

Минусы:
- Нужно помнить о преобразовании единиц
- Риск ошибок при конвертации
- Ограниченная точность (только целые числа)

### Money тип
`price MONEY`  
Плюсы:
- Специализированный тип для денег
- Автоматическое форматирование
- Встроенные функции

Минусы:
- Зависит от локали (разные форматы валют)
- Менее гибкий чем NUMERIC
- Нестандартный SQL тип

### Два поля (целая и дробная часть)
`
major_unit INTEGER  -- рубли/доллары
minor_unit INTEGER  -- копейки/центы
`
Плюсы:
- Полный контроль над округлением
- Легко работать с разными валютами
- Избегаем потерь точности

Минусы:
- Сложные вычисления
- Дублирование данных
- Нужны кастомные функции
